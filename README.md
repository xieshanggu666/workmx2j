# 🏅 青春杯 · 体育赛事编排与成绩管理系统（SportFlow）

一个综合性运动会/联赛的赛事编排与成绩管理平台，支持多项目、多赛制（单循环 / 小组赛+淘汰赛 / 单败淘汰 / 田径计时）编排，参赛队伍与运动员注册、赛程自动排定、比分录入、积分排名、奖牌统计与成绩册输出。适用于校运会、省市级联赛等场景。

> 视觉风格：**明亮运动活力风**（浅色底 + 活力橙/绿茵/天际蓝），与工程内其他项目（深色科技风）刻意区分。

## 技术栈

- **前端**：Vue 3 + Vite + Pinia（状态管理）+ 原生 SVG/条形可视化
- **后端**：Express + Node.js 内置 `node:sqlite`（需 **Node ≥ 22**，低版本可用 `npx -y node@22 server/index.js` 启动后端）
- **数据库**：SQLite（`server/event.db`）
- **通信**：REST API，Vite 代理 `/api` 到后端
- **启动**：`concurrently` 并行拉起前后端（后端 4170 / 前端 5203）

## 核心算法

- **单循环**：两两配对生成 `n*(n-1)/2` 场，积分最高者为冠军。
- **小组赛 + 淘汰赛**：分组循环 → 按每组积分排名（胜 3 / 平 1 / 负 0，净胜球次序）→ `A1 vs B2`、`B1 vs A2` 交叉半决赛 → 决赛 + 季军战。
- **单败淘汰**：半决赛 → 胜者晋级决赛、负者争季军。
- **淘汰赛平分决胜**：半决赛/决赛/季军战常规时间战平时，必须录入加时/点球决胜比分（不得再次持平），系统以决胜结果确定胜方并持久化到 `matches.winner`；晋级编排、奖牌结算、对阵展示统一读取该字段，未决胜前不会生成下一轮对阵。决胜比分不计入进失球。
- **田径计时**：成绩升序自动排名，前 3 结算金/银/铜。
- **奖牌统计**：按单位累计各项目冠军/亚军/季军。

淘汰赛对阵不是一次性预排，而是**按当前小组赛/半决赛真实赛果动态生成**——在"赛程编排"页当小组赛（或半决赛）完赛后点击"🧩 编排下一轮淘汰赛"，系统读取实时排名后自动填入对阵。

## 核心流程

**参赛资格审核**（报名审核页）：各单位提交队伍/运动员报名 → 组委会审核资格与名额（通过数不得超过项目名额上限）→ 通过后纳入参赛名单；循环赛项目若尚未开赛则自动重排对阵，把新队伍纳入赛程。退报或资格撤销时**同步处理受影响的对阵及成绩**：未赛场次判弃权（对手 3:0 胜），已赛场次取消成绩并重算积分榜与奖牌；田径项目删除该运动员成绩并重排名。

**审核幂等与事务**：审核（通过/驳回）、退报/撤销均为**幂等操作**——重复提交（双击/重试/并发）返回首次处理结果，不重复占名额、不重复触发赛程重排与级联；名额检查 → 占位 → 资格生效 → 赛程重排 → 积分/奖牌重建整体包裹在 `BEGIN IMMEDIATE` 单事务中（`withTransaction`），并发审核被串行化，任一环节失败整体回滚，杜绝超额参赛与半重排中间态。`POST /api/maintenance/repair` 提供**历史赛程统计修复**（幂等）：循环赛重复对阵去重、已通过报名名额序号重排、失格运动员残留成绩清理、积分榜与奖牌榜按权威赛果全量重建；服务启动时自动执行一次。

**赛事编排**：赛程编排（自动生成对阵）→ 录入比分（成绩录入页）→ 积分榜/排名自动更新 → 完赛阶段动态编排下一轮淘汰赛 → 单项目决出冠亚季 → 汇总至奖牌榜与报表中心。

## 赛事申诉复核（⚖️ 申诉复核页）

参赛单位可对三类对象提交异议：**球类已完赛场次比分**（限对阵双方单位）、**田径已录入成绩**（任何单位）、**他单位已通过的参赛资格**（不能申诉自身）；同单位同一对象存在未结案申诉时拒绝重复立案。组委会工作流为 **受理（pending→reviewing）→ 复核改判 / 驳回（驳回必填意见）**，申诉单位在结案前可**撤案**，撤案后允许凭新证据重新提交。

**改判原子级联**（全部包裹在 `BEGIN IMMEDIATE` 单事务，重复提交幂等返回首次结果）：

- **🏀 比分回写**：校验双方资格与淘汰赛决胜比分规则后回写 `matches`（比分/胜方/决胜比分，note 标注申诉编号），积分榜全量重建。
  - 小组赛/循环赛改判：按新积分排名**重新递补半决赛对阵**——待赛半决赛直接替换队伍且执法名单继续有效，已赛/已取消半决赛回退待赛重赛；随后决赛/季军战作废，待半决赛重踢后由既有淘汰赛编排重新生成。
  - 半决赛改判：以新胜/负方同步决赛与季军战，对阵变化或已完赛的场次**回退待赛重赛**（重赛场次保留原执法名单；void 恢复的场次自动联动排班）；对阵不变则原样保留。
  - 决赛/季军改判：直接回写赛果并重新结算金/银/铜，不影响下级轮次。
- **🏃 成绩回写**：更新计时成绩后**全量重排名次**，前 3 名奖牌重新结算。
- **🪪 资格改判**：复用资格撤销级联（未赛判弃权 3:0、已赛取消成绩、足球小组按新排名递补半决赛、统一淘汰赛 reconcile、田径删除成绩重排名）。

每次改判前后均抓取**奖牌快照与积分榜快照**，把单位级奖牌增减（金/银/铜 ±n）、队伍积分与名次变化连同回写明细、重赛/递补场次写入 `appeals.impact` 与 `appeal_logs`；比分类改判同时在 `assignment_logs` 留痕（`match_change`）。侧边导航对「待受理+复核中」数量显示角标，总览页展示待办申诉，报表中心提供改判审计表。

## 赛事安全事件处置（🚑 安全事件页）

医疗、安保、裁判、组委会四方岗位协同的事件闭环：**协同上报 → 组委会分级派单 → 联动处置 → 处置完成 → 复核结案**。事件编号 `SI-xxxx`，类型覆盖伤病急救 / 治安事件 / 冲突纠纷 / 场地器材 / 天气突发 / 其他。

- **协同上报**：任一方均可上报（带岗位与上报人），可指定事发场地与关联场次；上报后为「待分级」。
- **分级派单（组委会）**：评定 **重大 / 较大 / 一般**，指定医疗/安保/裁判/组委会**牵头处置方**，进入「处置中」；四方可随时追加「协同进展」（待结案后出现新进展自动退回处置中）。
- **状态闭环**：处置中 →（处置完成说明必填）待结案 →（结案总结必填）已结案；待结案可退回处置。**暂停场次未恢复/改期不能完成处置，仍有暂停场次不能结案，处置中不可直接结案。**

**🪪 联动证件暂扣**：处置中可暂扣任意赛事证件（原因必填），复用证件人工暂扣通道——入场核验一律以 `BADGE_BLOCKED` 拦截并计入异常审计，`access_logs` 的 block 记录标注事件编号。可在处置中逐项解除，结案默认统一解除；一张证件被多个事件暂扣时，**须全部事件解除后才恢复有效**。结案也可选择「继续暂扣」（责任追究/纪律调查，须注明原因，之后只能在证件管理页人工解除）。

**⏸️ 联动场次暂停 / ▶️ 恢复 / 📅 改期**：对关联待赛场次一键暂停后：① 入场核验对队伍/运动员/裁判统一拒绝（原因码 `MATCH_PAUSED`）；② 成绩录入锁定；③ 普通改期入口锁定，必须走事件处置。恢复即按原档期继续。改期直接复用赛程变更引擎（场地/裁判冲突检测、自动重排与整场补齐、无法解决冲突时整单原子回滚，可强制保留），成功后自动解除暂停并留存**原档期/原场地与事件编号**；暂停、恢复、改期同时写入 `access_logs`（danger/info/warn）与 `assignment_logs`（`match_change`）。

全部状态迁移与联动在 **`BEGIN IMMEDIATE` 单事务**内完成，重复提交/双击**幂等**返回首次结果，失败整体回滚。每一步（上报/分级/进展/暂扣/解除/暂停/恢复/改期/完成/退回/结案）都写入 `incident_logs` 时间线，联动结果汇总到 `incidents.impact`（暂扣/解除证件数、暂停/恢复/改期场次明细）。侧边导航对「待分级 + 待结案」显示角标，总览页展示未结重大事件与暂停场次，报表中心提供安全事件处置审计表。

## 赛事证件与入场核验（🪪 证件核验页）

运动员（队伍/田径单项）、裁判、场地工作人员人手一证（编号前缀 **T/A/R/S**，如 `T-0001`），入场口扫码后系统按**资格 + 赛程实时计算动态权限**，不存在永久通行证：

- **队伍**：资格 `approved` + 该场确为其赛程（必须是对阵双方）+ 核验场地与比赛场地一致 + 场次处于待赛状态；不指定场次时自动匹配其最近一场待赛。
- **田径运动员**：项目资格有效 + 核验场地为其项目场地（无对阵赛程，按检录口径放行）。
- **裁判**：必须在当前场次（或当前时段）的**在派执法名单**中（按排班入场），并携带主裁/助理/记录台角色；场地须与执法场次一致。
- **场地工作人员**：按**岗位 + 服务场地**授权，不依赖赛程——场地主管/医疗/安保→比赛区+工作区，器材→热身区+工作区，媒体→媒体区，志愿者→工作区。

**授权区域（zones）**随资格/岗位/赛程动态生成并在证件上留存快照；资格未生效（待审核/驳回）、退报、撤销资格、人员离岗时证件自动停用并收回区域；资格恢复自动激活。组委会可**人工暂扣**违纪证件（`block_manual`，资格恢复也不会自动解停，须人工解除）。服务启动时与 `POST /api/badges/sync` 提供全量证件同步（幂等，旧库自动补发）。

**核验结果四类**：✅ 放行、⛔ 拒绝（原因码 `BADGE_NOT_FOUND`/`BADGE_BLOCKED`/`NO_FIXTURE`/`WRONG_VENUE`/`NOT_ASSIGNED`/`MATCH_NOT_PLAYABLE`/`MATCH_PAUSED`（安全事件暂停））、⚠️ **强制放行**（值班主任必填原因留痕，计入异常审计）、🔁 重复核验（同证同日同场重复扫码返回首次结果，不重复回写）。全部判定在 `BEGIN IMMEDIATE` 单事务中完成。

**核验结果回写四域**（核验流水是唯一写入方）：

- **报名**：`registrations.last_checkin_at / last_checkin_result`（已核验/强制放行），报名审核页直接回显。
- **排班**：裁判签到写 `assignments.checkin_at`；调班/解除/对调时同步刷新场次到岗计数，避免旧签到残留。
- **比赛**：`matches.checkin_a_at/checkin_b_at`（双方到场）、`checkin_crew/checkin_crew_total`（执法到岗）、`admission_denied`（异常拦截计数）；场次取消/重赛/改判回退时清空到场数据重新核验。成绩录入页与赛程页显示到场/到岗/异常状态。
- **异常审计**：拒绝与强制放行写入 `access_logs`（severity danger/warn），证件发放/同步/暂扣/解除全量留痕；侧边导航对「今日拦截+强制放行」显示角标，报表中心提供异常原因分布与场次到场/到岗审计表。

## 裁判排班与场地协同（整场协同）

在「📍 场地裁判」页提供四个协同视图：

1. **排班总览**：按项目列出全部待赛场次的**整场执法名单（1 主裁 + 助理裁判 + 记录台；五人制足球配 2 名助理）**，可逐场安排、🤖 **一键整场智能排班**——逐场按角色补齐全部空缺席位。顶部统计卡给出**执法席位覆盖率（已排/应排）**与主裁/助理/记录台**分角色覆盖率**，预警条实时汇总名单不齐（空缺席位数）、撞档、跨专长、跨等级。
2. **场地协同**：各场地时段排布同时覆盖待赛与已完赛归档，实时区分待赛撞场和历史重叠；每场显示主裁与「助理/记录台 x/y」就位情况，可就地改期、自动重排或更正历史档案。
3. **裁判名册**：专长/等级/状态 + 已执法/待执法负荷（按 主裁·助理·记录台 拆分），冲突、跨专长、跨等级标记，支持录入新裁判。
4. **变更留痕**：排班、强制覆盖、临时调班（改派/同角色对调，必填原因）、解除、赛程变更、赛程新增/重排、完赛归档、退报取消解除——全部写入 `assignment_logs`，带原因与操作人可追溯。

**整场执法配置（`crewSpec`）**：球类项目每场需 `主裁×1 + 助理裁判×(足球2/其余1) + 记录台×1`；田径无裁判组。覆盖率、缺口与预警统一以"执法席位"为口径统计。

**智能排班算法（`autoFillCrews`）**：按时段升序逐场处理，每场依次补齐 主裁→助理→记录台 缺口；每个席位的候选裁判统一按 **专长精确匹配 → 同类别 → 综合执法 → 跨专长；等级与角色匹配优先（避免高等级裁判被过度占用）→ 待赛负荷低 → 无同时段冲突** 排序择优；已在该场名单中的裁判不重复占位。排班过程中即时感知同轮新增占用，天然完成工作量均衡。

**校验规则**：
- **时间冲突**：同一裁判同一 `time_label` 不得执法两场待赛（任意角色都算占用）；同场地同时段不得排两场。
- **专长**：专长不符默认拦截，填写原因后可**强制安排**并标记预警。
- **等级资质**：等级只能向下兼容（主裁可兼助理/记录台，助理不可当主裁、记录台不可当主裁/助理）；资质不符默认拦截，可强制安排并标记「跨级」。临时调班（改派/同角色对调）同样做专长、等级与冲突预检，对调仅限相同执法角色。

**赛程变更联动整场执法安排**：调整**待赛场次**时间/场地时，系统在单事务中先应用变更、再基于变更后的全局状态检测场地与裁判冲突；默认开启**自动重排**，逐席释放冲突裁判并按专长/等级/负荷自动改派，随后补齐该场主裁/助理/记录台缺口。场地撞场或存在无合格替补的裁判冲突时，整笔改期（场次、排班、自动改派、留痕）**原子回滚**，并补写 `reschedule_rollback` 留痕；仍需强行调整时可选择强制保留冲突并留痕。调整**已完赛场次**时只更正历史时间/场地档案，比分、积分和已归档执法名单不变，且必须填写更正原因；场地视图会区分待赛撞场与历史归档重叠。新生成的淘汰赛/半决赛、循环赛重排的新场次均**自动整场协同排班**（补齐主裁/助理/记录台，无可用裁判的席位留待排班页）；报名通过触发循环赛重排时，旧场次执法安排全部解除并留痕；退报/撤销资格导致的弃权（判 3:0 完赛 → 执法记录归档）与成绩取消（场次 void → 解除在派裁判）均联动；比分录入页与赛程页显示整场名单，录入比分时未派主裁或缺助理/记录台均返回预警；总览页与报表中心展示**已完赛归档 + 待赛排班**合并覆盖率及分待赛/已完赛口径，报表中心同步分角色覆盖率、按角色拆分的执法工作量、场地冲突与最新变更。
